# 出题模板

> 本文件包含完整的出题规则、题型库和出题流程。出题时必须先读取本文件。

---

## 难度分级

根据用户当前掌握程度，自动选择难度：

| 难度 | 适用对象 | 题目特征 | 示例 |
|------|---------|---------|------|
| ⭐ 基础 | 未学过/初步了解 | 概念辨析、语法填空、单知识点 | "v-if 和 v-show 的区别是什么？" |
| ⭐⭐ 进阶 | 能独立使用 | 多知识点组合、代码补全、小功能实现 | "用 v-for + v-if 实现：只显示成绩 ≥60 的学生" |
| ⭐⭐⭐ 挑战 | 熟练掌握 | Bug 修复、设计模式、综合小项目 | "这段代码有 3 个 bug，找出并修复" |
| ⭐⭐⭐⭐ 开放 | 熟练掌握+ | 架构设计、性能优化、多语言对比 | "用两种方式实现同一个功能，对比优劣" |

## 编程语言题型

- **概念题**：解释某个概念的含义和用途
- **代码填空**：给出部分代码，让用户补全缺失部分
- **代码纠错**：给出有 bug 的代码，让用户找出并修复
- **预测输出**：给出代码，让用户预测运行结果
- **动手实现**：给出需求，让用户从零写代码
- **设计题**：给出场景，让用户设计解决方案（不写代码，先说思路）
- **重构题**：给出能跑但写得差的代码，让用户优化

---

## 区块链题型

- **合约审计**：给出一段 Solidity 合约，找出安全漏洞
- **Gas 优化**：给出能跑但 Gas 消耗高的代码，要求优化
- **原理分析**：解释某个机制的工作原理（如"描述一笔交易从提交到上链的完整流程"）
- **架构设计**：设计一个 DApp 的合约架构和交互流程
- **安全场景**：给出攻击场景，设计防护方案

---

## 数据库题型

- **SQL 编写**：给出表结构和需求，手写查询语句（SELECT/JOIN/子查询/聚合）
- **Schema 设计**：给出业务场景，设计表结构和关系（ER 图）
- **查询优化**：给出慢查询，分析执行计划并优化（加索引、改写查询）
- **事务分析**：给出并发场景，分析隔离级别和数据一致性问题
- **NoSQL 选型**：给出需求，对比关系型 vs NoSQL 的适用场景
- **链下存储设计**：设计 DApp 的链上+链下数据架构（The Graph / IPFS / Redis）

---

## 工具链题型

- **命令匹配**：给一个目标，选择正确的 Git 命令
- **流程还原**：给出一系列操作，还原出完整的 Git 历史
- **冲突解决**：模拟 merge 冲突，要求解决
- **工作流设计**：给一个团队协作场景，设计分支策略和 PR 流程

---

## 跨领域综合题

同时涉及多个领域的综合场景：
- 示例："用 Solidity 写一个 ERC20 合约，用 Hardhat 测试，用 Git 管理项目，最后部署到 Sepolia 测试网"
- 示例："为一个 NFT 市场设计数据层：合约事件日志 → The Graph 索引 → PostgreSQL 存储用户资料 → Redis 做实时竞价排行榜"

---

## 错题重练

- 用户做错的题目记录到 progress.json 的 exercises 中（result 字段标记"未通过"）
- 下次出题时，优先出与错题相关的变体题（同知识点，不同场景）
- 连续 2 次通过同一知识点的变体题 → 标记该知识点掌握程度提升

---

## 出题流程

1. 用 `python3 {{SKILL_DIR}}/scripts/tutor_progress.py list` + `get <领域>` 读取进度，确定用户当前水平（跨领域汇总；进度文件 `{{SKILL_DIR}}/references/progress.json` 实测 34029 字节 / 约 34 KB，不要用文件读取工具全文 read）
2. 选择难度等级和题型（优先出用户薄弱环节的题）
3. 出题后等用户作答
4. 批改 + 引导式讲解（不是只说对错，要解释为什么）
5. 更新进度：`python3 {{SKILL_DIR}}/scripts/tutor_progress.py exercise <领域> <名称> <通过|未通过> [备注]`
   - 记录 shape 为 `{name, date, result, domain, notes}`，`domain` 由脚本自动填当前领域，`result` 只能是 `通过` / `未通过`（错因、说明写进 `notes`，不要塞进 `result`）
