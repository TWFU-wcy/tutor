# 进度追踪 Schema（教学开场必读）

> 本文件是**每次教学开场必读**的最小集：掌握程度等级、自动降级规则、读写流程。
> 进度文件的数据结构、字段含义、别名表、展示格式在 `progress-data.md`（按需再读，不必开场读）。
> 命令语法见 `SKILL.md` 的「进度追踪」一节。

## 掌握程度等级（唯一权威）

| 等级 | 含义 | 提问策略 |
| --- | --- | --- |
| 未学过 | 从未接触该知识点 | 从难到易详细引导，逐步降级到用户能回答 |
| 初步了解 | 知道概念但不能独立写代码 | 跳过基础定义，重点引导应用和细节 |
| 能独立使用 | 能独立完成常见任务 | 回忆式引导激活记忆，直接进阶 |
| 熟练掌握 | 能灵活运用并理解底层原理 | 几乎不提问，直接高阶应用 |

升级路径：未学过 → 初步了解 → 能独立使用 → 熟练掌握。

## 降级规则（两阶段，自动检查 lastPracticed）

教学开场读进度时，逐个检查知识点的 `lastPracticed`：

**第一阶段：预警（12-14 天）**
- 距上次练习 12-14 天，且等级为「能独立使用」或「熟练掌握」→ 开场提醒："XX 快两周没练了，要不要复习一下？"
- 不自动降级，等用户决定
- 用户说"不用复习" → 跳过预警，继续按原等级教学

**第二阶段：降级（>14 天）**
- 「能独立使用」→ 降为「初步了解」
- 「熟练掌握」→ 降为「能独立使用」
- 「初步了解」「未学过」不降级

**约束：**
- 单次教学开场最多降 1 个等级（不会从「熟练掌握」直接掉到「初步了解」）
- 降级后在 `notes` 追加 `⚠️ 已降级：距上次练习 X 天`
- 用户重新练习并升级时，清理 notes 里的降级备注，保留用户原有备注

## 读写流程

1. **开场**：`list` 看全局 → 按需 `get <领域> [概念]`（含上面的降级检查）
   - 不要用文件读取工具全文加载 `progress.json`（约 35KB），用脚本只取需要的片段
2. **教学中**：根据用户表现判断等级变化，记下薄弱点
3. **结束时**：按 `SKILL.md`「强制写入时机」执行写命令（`update` / `add-note` / `weak` / `exercise` / `milestone`）
   - 必须先真的调用工具，不允许只输出文字说"已记录"

## 写入安全与权限

- 脚本写入用「临时文件 + 原子替换」，写一半被打断也不会损坏数据
- 进度文件损坏时自动备份为 `progress.json.bak` 并重建
- 若会话只能写工作目录（只读沙箱 / DSH 的 `workspace-write` 等），写入会被拒绝并给出提示：此时告知用户放开该目录写权限，**读取不受影响**，不要因此跳过教学或谎称已记录
- 同一份进度文件若被多个 agent 同时写入，仍可能互相覆盖（无文件锁）——正常情况下一个会话一个写者，无需担心
