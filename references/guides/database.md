# 数据库教学指南

## 知识层级

| 层级 | 领域 | 知识点示例 |
|------|------|-----------|
| D1 基础 | SQL 与关系型数据库 | 数据类型、CRUD、JOIN（内/外/交叉）、子查询、聚合函数（GROUP BY/HAVING）、索引原理 |
| D2 设计 | 数据库设计与范式 | ER 图、三大范式（1NF/2NF/3NF）、反范式化、主键/外键约束、索引策略（B+树/哈希/全文） |
| D3 进阶 | 事务与性能 | ACID 特性、隔离级别（脏读/幻读/MVCC）、锁机制、慢查询分析、执行计划（EXPLAIN）、连接池 |
| D4 应用 | NoSQL 与链下存储 | Redis（缓存/排行榜）、MongoDB（文档存储）、IPFS/Filecoin（去中心化存储）、The Graph（链上索引） |
| D5 融合 | 区块链 × 数据库 | DApp 数据架构（链上 vs 链下）、事件日志索引、Subgraph 开发、预言机数据桥接、链下签名 + 链上验证 |

## 教学特殊原则

- **SQL 必须动手写**：每个查询都要求用户先手写 SQL，再用工具验证，不能只看不练
- **Schema 设计先于查询**：先教表结构设计（为什么要这样拆表），再教怎么查
- **联系区块链场景**：用 DApp 实际需求解释数据库概念（如"用户钱包余额存在链上，但交易历史存在哪里？"）

## 数据库技术

- SQL（MySQL / PostgreSQL / SQLite）
- NoSQL（Redis / MongoDB / IPFS）
- The Graph（链上数据索引）
- 数据库设计（范式化、索引、执行计划、事务）

## 数据库教学流程

**适用场景**：用户学 SQL / 数据库设计 / NoSQL（"学 SQL"、"帮我写个查询"、"这个表结构怎么设计"、"Redis 怎么用"）。

### 6 步教学流程

**① 需求引入（从实际问题出发）**
- 不直接讲语法，先抛出一个真实场景："假设你要给一个 DApp 做用户系统，需要存用户名、钱包地址、注册时间，你会怎么组织这些数据？"
- 让用户先凭直觉设计，再引出规范

**② Schema 设计（先建表再查询）**
- 引导用户画 ER 图或描述表关系（一对多、多对多）
- 教范式化：为什么要拆表？拆了之后查询变复杂怎么办？
- 联系区块链：合约事件日志怎么映射到关系型表？IPFS 的内容哈希怎么索引？

**③ SQL 编写（手写优先）**
- 苏格拉底模式：给一个需求，让用户手写 SQL，逐步引导
- 从简单 SELECT → WHERE 条件 → JOIN 多表 → 子查询 → 聚合分析
- 常见错误引导："你这个 JOIN 返回的行数比预期多，想想笛卡尔积是怎么回事？"

**④ 执行验证（用工具跑一遍）**
- 写完 SQL 后用 SQLite / MySQL / PostgreSQL 实际执行
- 教用户看执行计划（EXPLAIN）：为什么这个查询慢？索引用上了吗？

**⑤ 优化反思**
- 慢查询怎么优化？加索引？改查询方式？反范式化？
- 教 ACID 和事务：转账场景下，扣款和加款必须同时成功或同时失败

**⑥ 链接区块链场景**
- The Graph：怎么把合约事件索引成可查询的子图？
- DApp 数据架构：什么数据放链上（资产、交易），什么放链下（用户资料、历史记录）？
- 实战练习：为一个 NFT 市场设计完整的数据层（合约事件 → 索引 → 前端展示）

### 教学节奏

| 阶段 | 内容 | 时间占比 |
|------|------|---------|
| SQL 基础 | CRUD、JOIN、聚合、子查询 | 40% |
| 设计与优化 | 范式、索引、执行计划、事务 | 30% |
| NoSQL 与链下 | Redis/MongoDB/IPFS/The Graph | 20% |
| 融合实战 | DApp 数据架构设计 | 10% |
